# Skincare landing page — Bangladesh

A single-page, fully static landing site for a Bangladeshi skincare brand.
Customers arrive from Facebook ads, press **অর্ডার করুন**, fill a short form, and
the order is handed to the owner's WhatsApp as a pre-filled message. Payment is
manual via bKash.

There is no backend, no database, no accounts and no payment gateway.
`npm run build` produces a plain `dist/` folder.

---

## Quick start

```bash
npm install
npm run dev          # http://localhost:4321
```

| Command | What it does |
| --- | --- |
| `npm run dev` | Dev server with hot reload |
| `npm run build` | Production build into `dist/` |
| `npm run preview` | Serve the built `dist/` locally |
| `npm run check` | TypeScript + Astro type check |
| `npm run test` | Unit tests (Vitest) |
| `npm run audit` | Report real gzipped bundle sizes, fail if over budget |
| `npm run placeholders` | Regenerate the placeholder artwork |
| `npm run verify` | check + test + build + audit, in order |

Node 22.12 or newer is required.

## 1. Everything you need to edit: `src/config/site.ts`

This one file is the source of truth. No component hard-codes a price, a phone
number or a product name.

Two markers to search for:

- **`REPLACE`** — placeholders you *must* change before going live.
- **`«placeholder»`** — invented marketing copy to rewrite in your own words.

### The must-change list

| Field | Notes |
| --- | --- |
| `brandName` | Appears in the header, footer, page title and the social card |
| `orderPrefix` | Two letters used in order IDs, e.g. `GS` gives `#GS-3K7M2P` |
| `whatsappNumber` | **International format, digits only** — `8801712345678`. No `+`, no spaces. Getting this wrong silently sends orders nowhere |
| `bkashNumber` | The number shown to customers, e.g. `01712345678` |
| `bkashAccountType` | `'Personal'` shows "Send Money", `'Merchant'` shows "Payment" |
| `phone` | Shown in the footer |
| `address` | Footer + Organization schema |
| `facebookPage` | Footer link |
| `facebookPixelId` | Leave `''` to load no tracking at all |
| `seo.title` / `seo.description` | Search and social snippet |

### Changing delivery charges

```ts
deliveryCharge: {
  insideRajshahi: 60,
  outsideRajshahi: 120,
},
```

That is the only place these numbers exist. The checkout summary, the WhatsApp
message, the closing section and the footer policy all read from here.

### Adding or changing a product

Add an entry to `products`. Every field is typed, so `npm run check` will tell
you if you miss one.

```ts
{
  id: 'night-repair-cream',          // stable slug — also the DOM id and analytics id
  name: 'Night Repair Cream',        // English, never translated
  line: 'her',                       // 'her' | 'him' | 'unisex'
  price: 1350,
  oldPrice: 1600,                    // optional — omit to hide the discount
  size: '50ml',
  step: 'protect',                   // 'cleanse' | 'treat' | 'protect'
  badge: 'নতুন',                      // optional ribbon
  shortBenefit: 'এক লাইনে মূল উপকার।',
  description: 'দুই-তিন বাক্যে বিস্তারিত।',
  keyIngredients: ['Retinal 0.05%', 'Squalane'],
  howToUse: ['রাতে পরিষ্কার মুখে লাগান।'],
  image: '/products/night-repair-cream.png',
  imageAlt: 'Night Repair Cream-এর ৫০ মিলি জার',
}
```

Then drop `night-repair-cream.png` into `src/assets/products/` — see §2.

The product appears automatically in the best-seller grid, the For Her / For Him
split, the filtered showcase, its own scroll-driven story row, the checkout
dropdown and the Product JSON-LD.

### The routine builder

`routineMap` decides which product fills each of the three steps per line:

```ts
routineMap: {
  her: { treat: 'vitamin-c-glow-serum', protect: 'hydra-barrier-moisturizer' },
  him: { cleanse: 'oil-control-face-wash', protect: 'after-shave-calm-balm' },
},
```

A step you leave out renders a dashed **"এই ধাপের প্রোডাক্ট শীঘ্রই আসছে"** tile.
With the seeded catalogue, *her* has no cleanser and *him* has no treatment, so
you will see one of those tiles in each line until you add those products.

## 2. Replacing the images

> **Important:** artwork lives in **`src/assets/`**, not `public/`.
> Astro only generates AVIF/WebP and responsive `srcset` for imported assets.
> Anything in `public/` is served byte-for-byte and would break the speed
> budget. `site.ts` keeps writing readable paths like
> `/products/name.png`; `src/lib/images.ts` maps those to the real files.

Everything currently in `src/assets/` is a flat illustration generated by
`scripts/gen-placeholders.mjs`. It is deliberately *not* a fake photograph.
Replace it with the real thing:

| File | Size | Ratio | What to shoot or buy |
| --- | --- | --- | --- |
| `src/assets/products/<id>.png` | 1200 × 1600 | 3:4 | The bottle alone, **transparent PNG**, centred, lit from the upper left. Transparency matters — the product sits on four different coloured backgrounds and tilts in 3D |
| `src/assets/scenes/model-hero.png` | 1000 × 1250 | 4:5 | A woman applying product, warm neutral background, waist-up |
| `src/assets/scenes/model-council.png` | 1200 × 900 | 4:3 | A woman, same treatment, landscape crop |
| `src/assets/scenes/model-square.png` | 900 × 900 | 1:1 | Secondary lifestyle shot |
| `src/assets/scenes/scene-1/2/3.png` | 900 × 900 | 1:1 | The product styled in a scene — on stone, in foliage, on fabric |
| `src/assets/botanical/*.png` | ~400 × 400 | 1:1 | Cut-out flowers, leaves and dried stems, **transparent PNG**, soft drop shadow |
| `public/og.jpg` | 1200 × 630 | 1.91:1 | Social share card. Stays in `public/` — it is fetched by URL |
| `public/favicon.svg`, `icon-*.png` | — | 1:1 | Brand mark. Stays in `public/` |

Keep the filenames identical and nothing else needs touching. Use a different
name and you must update `image` in `site.ts` to match.

**All model imagery is female**, per the brief. The placeholder generator only
draws women; keep that in mind when commissioning photography.

Source files are large PNGs on purpose — Astro downsizes and re-encodes at build
time, so hand it the highest quality you have.

## 3. How the order flow works

1. Any **অর্ডার করুন** button opens the checkout with that product preselected.
2. The customer fills name, mobile, district, address and delivery area.
3. The summary shows subtotal, delivery and total live.
4. On confirm the browser generates an order ID, builds the message, and opens
   `https://wa.me/<your number>?text=<the order>`.
5. A success screen shows the order ID, the total, the bKash number with a copy
   button, and an **আবার WhatsApp খুলুন** link in case the redirect was blocked.

The message template is built by `src/lib/buildOrderMessage.ts` and is covered
by unit tests, because that string is the entire order record you receive.

```
আসসালামু আলাইকুম, আমি একটি অর্ডার করতে চাই।

🧾 Order ID: #GS-4821

🧴 Product: Vitamin C Glow Serum
📦 Quantity: 2
💰 Subtotal: ৳1,700
🚚 Delivery: ৳60
✅ Total: ৳1,760

👤 Name: ...
📞 Mobile: ...
📍 Address: ..., District

💳 Payment: bKash (01XXXXXXXXX)
আমি মোট ৳1,760 পাঠিয়েছি / পাঠাচ্ছি। ট্রানজেকশনের স্ক্রিনশট নিচে পাঠাচ্ছি।

📝 Note: ...
```

**Worth knowing:** an order only reaches you when the customer actually sends
that WhatsApp message. If they close the tab first, you never see it. The
success screen exists to make that recoverable — it keeps the order ID, the
total and a second WhatsApp link on screen.

Mobile numbers are normalised before sending, so a customer pasting
`+880 1712-345678` still reaches you as `01712345678`.

## 4. Deploying to Cloudflare Pages

1. Push this folder to a Git repository.
2. Cloudflare Pages → **Create a project** → connect the repository.
3. Settings:
   - **Framework preset:** None (or Astro)
   - **Build command:** `npm run build`
   - **Output directory:** `dist`
   - **Node version:** `22.12.0` or newer — set `NODE_VERSION` in the
     environment variables if the default is older
4. Deploy.

**Before the first deploy**, set the real production URL in `astro.config.mjs`:

```js
const SITE = 'https://your-domain.com';
```

It is used for the canonical link, the Open Graph URLs and `sitemap-index.xml`.
Leaving the placeholder will not break the page, but search engines and Facebook
will be given the wrong address.

The build downloads the fonts from Google once and self-hosts them, so the build
machine needs network access. Nothing is fetched from Google at runtime.

## 5. Facebook Pixel

Leave `facebookPixelId: ''` and **no third-party script is loaded at all**.

Set an ID and the pixel loads after the page is interactive, then fires:

| Event | When |
| --- | --- |
| `PageView` | On load |
| `ViewContent` | When a product's story section is 40% visible — once per product |
| `InitiateCheckout` | When the checkout opens |
| `Lead` | On a successful confirm, with `value` and `currency: 'BDT'` |

## 7. Design notes worth keeping

**Two deliberate deviations from the supplied reference**, both for
accessibility:

- The reference uses a vivid `#F2701E` behind white button labels. That is
  2.95:1 and fails WCAG AA. Interactive surfaces use a deeper `#C24D10`
  (4.81:1) instead. The vivid hue survives as `--color-orange-bright` for
  decorative fills and badges that carry dark text.
- The bKash block is a neutral card with the word "bKash" set in the site's own
  type. The official bKash logo and brand pink are trademarks and are not used.
  Same reasoning for the WhatsApp icon: it is a custom handset-in-bubble glyph
  from the site's own icon set, not the WhatsApp mark. If you have permission to
  use either mark, swap them in `src/components/ui/Icon.astro`.

Run `node scripts/contrast.mjs` after changing any colour — it checks every
foreground/background pair in the design and exits non-zero on a regression.

**Structured data:** `Organization`, one `Product` per item, and `FAQPage` are
emitted. Review and `aggregateRating` markup is deliberately *not*, because the
seeded reviews are invented — shipping fabricated ratings as structured data is
what search engines penalise. Add it once the reviews in `site.ts` are real.

**Interactions without JavaScript.** The showcase filter, the ingredient
explorer and the routine toggle are radio groups driven by CSS `:has()`, and the
FAQ is native `<details>`. They work with scripting disabled and get keyboard
support for free.
